# TV Setup

A consent-first Android-phone and iPhone installer for Android TV. **Experimental preview, not a production release.** No TV is contacted by building or running tests.

[Download the Android phone preview](https://github.com/akshatagarwl/tv-setup/releases/tag/v0.1.0-preview) — locally debug-signed, not hardware-validated. Install it on your **phone**, not the TV. iPhone source builds are available below; there is no signed iPhone/TestFlight distribution yet.

## Implemented

1. Enter one TV's private IPv4 address and classic network-ADB port.
2. Authorize the phone **on the TV**; iPhone also requests Local Network permission.
3. Read Android version, CPU architecture, TV capability and only the relevant package-presence checks. The owner profile is required.
4. Opt into TizenTube, Google voice-search handoff and/or Proton VPN. Nothing is selected by default; voice handoff requires TizenTube.
5. Preview architecture-specific downloads, SHA256 pins and existing apps that will be kept.
6. Explicitly confirm the TV is not in use before installing missing apps.
7. Verify pinned size, whole-file SHA256 and publisher certificate; stream the APK to package manager **without reinstall/update flags**; check success and package presence.
8. Finish sign-ins, accessibility and VPN prompts yourself on the TV, when convenient. Manual undo guidance is included.

The installer does **not** open TV apps, replace existing packages, read app profiles, request microphone access, change accessibility or Assistant settings, filter remote keys, change launchers, connect a VPN, enable lockdown or import private channel lists. It stops on errors; already-finished installs are not silently removed. Cancellation cannot guarantee an APK which reached Android package manager did not finish installing—reconnect to check.

### Important limits

- **Classic TCP ADB only**, not Android wireless-debugging pairing codes/TLS. Use a trusted LAN; classic ADB is not an encrypted, mutually authenticated transport. Never expose its port to the Internet.
- Android phone: API 26+. iPhone: iOS 16+. TV compatibility is checked per APK; current TizenTube artifacts cover ARM32/ARM64.
- These are working builds and fake-transport tests, **not handset/real-TV validation**. Authorization, Local Network prompts, installation, physical-mic search, held-volume behavior and playback still need authorized hardware testing.
- APKs are pinned, but official TizenTube's APK loads upstream web scripts from JSDelivr. **Those runtime scripts are not pinned by this preview.** Shipping a reviewed, self-contained/pinned custom build is a later milestone.
- Guided text is present, not automated sign-in or permission grants. Proton account capabilities, restricted-video availability, auto-connect, reboot recovery and LAN compatibility are not verified.
- Channel lists, YouTube-branded shortcut/launcher integration, persistent receipts and one-tap rollback are **not implemented**. No personal list or unlicensed community dataset is shipped.
- No TestFlight/App Store submission. An Apple developer team, provisioning, device testing, production icons and release review are still required. Store approval is not guaranteed.

## Build

### Android

JDK 17, Android SDK platform 34 and build-tools 34.0.0:

```sh
python3 scripts/sync-resources.py
bash scripts/build-android.sh
```

Output: `dist/tv-setup-debug.apk`, locally debug-signed. Private debug signing material stays in ignored `private/`. The build does not install on a phone or TV. Set `JAVA_HOME` and `ANDROID_SDK_ROOT` for your environment. This small preview uses native Java UI and SDK tools directly; a Gradle/CI/store release pipeline is a future step. Target SDK 34 is for local testing, not a claim of current Play Store eligibility.

### iPhone

Xcode with the iOS SDK, Swift 6 and XcodeGen:

```sh
python3 scripts/sync-resources.py
cd ios
xcodegen generate
xcodebuild -project TVSetup.xcodeproj -scheme TVSetup \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build
```

For a phone, open `ios/TVSetup.xcodeproj`, choose your signing team and provision your own device. The generated project is ignored; `project.yml` is the source of truth. An unsigned `.app` is not an installable iPhone distribution. Developer-account access is not embedded or assumed.

## Tests and release pins

```sh
bash scripts/test.sh
```

Tests: Swift planner/codec/transport/certificate tests, Java planner/codec/transport checks and Python resource/privacy invariants. They use fake ADB peers and do not enumerate or connect to any device. First use downloads pinned Swift dependencies and a hash-checked test-only Android JSON jar.

`shared/catalog.json` is the single bundled recipe source. Platform resources are generated byte-for-byte; `scripts/sync-resources.py --check` detects drift. There is no remote catalog, imported script execution or automatic update feed.

Release-preparation verification (not part of normal installation):

```sh
python3 scripts/verify-releases.py --download tizentube-arm64
python3 scripts/verify-releases.py --apk proton=/path/to/official-proton.apk
```

This checks full APK v2 signatures with Android `apksigner`, hashes, certificate pins, package/version, minimum SDK and expected ABI. The iOS client extracts the certificate from the **already whole-file-hash-verified** v2 block; that extractor is not a replacement for independent APK signature validation. Android uses its package archive parser after hash validation. TV package manager performs installation checks.

Optional Swift release-fixture test: place reviewed APKs at `tizentube-arm.apk`, `tizentube-arm64.apk`, `proton.apk` under a private directory and set `TVSETUP_RELEASE_APK_DIR` before `swift test`. Without that variable the fixture test skips, never downloads.

## Public companion projects

- [TV Channel Lists](https://github.com/akshatagarwl/tv-channel-lists): MIT builder and CC0 curated channel preferences. Personal and license-unclear combined datasets stay private. This installer does **not yet import** the public list.
- [TizenTube filter fork](https://github.com/akshatagarwl/TizenTube/tree/feat/pr720-channel-block): source switches and compressed channel matching; existing installed snapshots are not changed by publishing list updates.
- [Voice-search handoff](https://github.com/akshatagarwl/tv-search-handoff): retains Google recognition without remote-key filtering.
- [Permission-free TV shortcut](https://github.com/akshatagarwl/tv-youtube-shortcut): original generic public artwork, no account data or signing keys.

## Architecture and documentation

- `shared/`: versioned catalog, public companion APK, generated license notices. No account data or lists.
- `android/`: foreground-only phone UI, strict planner, verified downloader and serial ADB adapter.
- `ios/`: SwiftUI phone UI, testable Swift core and XcodeGen spec.
- `vendor/`: reviewed codec/RSA subsets; original connection/stream implementations are not used.
